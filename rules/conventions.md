# Conventions Rules

1. Names such as `tmp`, `data`, `value`, `x`, `t1`, or `col1` are weak unless the surrounding context makes them meaningful.
2. Aliases should describe the role of the object when that can be done without making the SQL harder to read.
3. Naming comments should stay secondary to correctness and security findings.
4. If the project naming convention is not provided, do not invent one; only flag names that are clearly vague or inconsistent.
5. Use `LOW` severity for style-only issues unless they also reduce clarity enough to create a maintenance risk.
